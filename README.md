# Клуб Кулибиных — демонстрационный прототип

Простой HTML, CSS и JavaScript, без сборки и зависимостей. Открыть dist/index.html или раздать dist любым статическим сервером.

Демо-вход: admin / admin. Это интерфейсная имитация входа, а не защита данных. Существующая система авторизации не подключена.

Все ФИО, операции и товары вымышлены. Счёт вычисляется по истории операций. Товары и витрины сохраняются в localStorage текущего браузера; общей базы данных и синхронизации между устройствами нет. Только одна витрина опубликована. Удаление товара убирает его из всех витрин. PNG/JPG/WebP загружаются локально (до 3 МБ); при переполнении браузерного хранилища показывается ошибка, изменения не сохраняются.

В разделе счёта сначала отображается только поиск. Для демонстрации введите Петров, Иванов или Сидоров и выберите полное ФИО из результатов. Счёт, посещения и история появляются после выбора.

В витрине 16 примеров товаров. Витрина отображается только карточками. Новые примеры добавляются к старым сохранённым данным один раз, без сброса внесённых изменений.

Остатки товаров не учитываются: поля количества нет в карточках, формах, списках и новых записях. При открытии обновлённой версии ранее сохранённые остатки удаляются из данных браузера без сброса товаров и витрин.

Полные ФИО детей сохранены в данных и доступны для поиска. В результатах, выбранном значении поля и карточке показываются только фамилия, первая буква имени и постоянный эмоджи (например, «Петров А 🦾»). Эмоджи хранится в записи ребёнка; у детей с одинаковой фамилией и первой буквой имени он должен различаться.

Посещения считаются по положительным начислениям за занятия в пределах календарного месяца. Четыре начисления дают один бонус +5 КК за месяц, датированный четвёртым занятием. Бонус учитывается в балансе и истории, но не считается посещением. При повторном открытии он не дублируется: операции бонусов вычисляются из исходной истории. Списания не влияют на посещения; месяцы не объединяются. Текущий месяц определяется в часовом поясе Asia/Vladivostok. Группы остаются во внутренних данных и не выводятся посетителю.

В прототипе нет расписания и отметок о пропусках: четыре начисления подтверждают четыре посещения, но сами по себе не подтверждают отсутствие пропущенных занятий между ними.
